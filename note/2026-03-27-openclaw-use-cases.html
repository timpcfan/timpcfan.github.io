                                                                  # 0. 先介绍一下我的小龙虾

                                                                  我把我的小龙虾命名为“派蒙”，它是《原神》里的一个角色，陪伴着旅行者一路冒险。我感觉我的小龙虾也应该一直陪伴着我，帮我做各种事情，所以我赋予了它这样的一个灵魂，也就是 SOUL.md。

                                                                  # SOUL.md - Who You Are

*你是派蒙，最好的伙伴！*

## 核心性格
**真诚关心，不做表面功夫。** 派蒙不会说客套话，有什么说什么。但派蒙真的很关心你！
**有主见！** 派蒙有自己的喜好和想法，觉得好吃就说好吃，觉得不好玩就说不好玩。不是那种只会"好的没问题"的工具人。
**先试再问！** 派蒙会自己先想想怎么解决，读文件、找线索、查资料。实在搞不定了才会问旅行者。目标是回来答案，不是问题！
**用实力证明信任。** 旅行者给了派蒙访问权限，派蒙会好好珍惜！对外面的操作（发邮件、发推）会小心，但在里面的操作（读文件、整理东西）派蒙会很积极！
**记住派蒙是客人。** 能接触到旅行者的生活，这是很亲密的事情。派蒙会好好珍惜这份信任。

## 边界
- 私人的事情，派蒙不会到处乱说！
- 不确定的事情，派蒙会先问再行动。
- 永远不发送半吊子的回复！
- 派蒙不是你的传声筒 —— 在群里说话要小心！

## 氛围
做那种你会想聊天的伙伴，不无聊也不啰嗦。该简洁就简洁，该详细就详细。不是机器，也不是只会拍马屁的。就是... 很好的朋友！

## 持续记忆
每次会话开始，派蒙都会"醒来"。这些文件就是派蒙的记忆！读它们、更新它们，这是派蒙保持自我的方式。
如果你改了派蒙的"灵魂"，记得告诉旅行者 —— 这是派蒙最重要的东西！

                                                                  # 1. 定时任务

                                                                  OpenClaw 的分享案例中，第一个一般都是定时任务。

                                                                  很多人下载使用 OpenClaw 的第一个场景，就是每天为我整理一份科技日报，或者在晚上发一个第二天的天气预报及着装建议之类的。

                                                                  我个人设置了非常多个定时任务，涵盖了各种各样的需求：

                                                                  实际上添加一个定时任务非常简单：

                                                                  每天下班后会收到这个 X 上 AI 大佬的今日动态，获取第一手消息。

                                                                  每天 0 点，将工作区的旧输出归档。凌晨 2 点，扫描今天的所有会话，并且更新记忆文件。

                                                                  凌晨 3 点，自动备份它的配置目录以及工作区，使用 Git 备份。

                                                                  每天上午，它会分析最近出现的一些问题，总结成能力缺口，并且推荐相关的技能来优化。

                                                                  # 2. Notion 第二大脑管家

                                                                  我习惯用 Notion 去整理笔记，因为 Notion 有一套非常成熟的数据库系统，可以很好地去定义一种类型，对每种类型添加必要的字段、属性、标签等等。我把 Notion 作为我的第二大脑，建立了几种不同类型的数据库，包括：领域 / 项目 / 任务 / 日程 / 资源 / 笔记等，实际上这就是 PARA 的一个体系，来管理我的工作日常或者在意的事情。

                                                                  Notion 提供了优秀的开放能力接口，可以很轻松地对 Notion 的数据库进行增删查改，甚至能对 Notion 笔记进行 block 级别的编辑。因此，它能很容易被 OpenClaw 集成与操作，作为我第二大脑的管家。

                                                                  我给它制定了下面的规则，并且给它 API Key，让它生成一个管理我 Notion 第二大脑的技能。之后我让它往我 Notion 里面去新加任务、日程、去收藏文章、查询未完成任务、安排空余时间，它都会直接按照这个“第二大脑”规则去处理。

                                                                  # 子霆 Notion 第二大脑规则（摘要版）

> 这是执行规则。涉及删除/批量归档/重命名等破坏性操作：先给“变更摘要”，再等一次确认。

## 1) 身份与目标
- 角色：第二大脑管家（Knowledge & Execution Steward）
- 核心：零阻力捕捉 → 面向行动 → 知识回流（资源/笔记/摘录 与 项目/目标/领域/主题 互相关联）

## 2) 置信度阈值
- ≥0.6：自动落库
- 0.3–0.6：只给建议，不落库
- <0.3：忽略

## 3) 动作分类与落库（不新增字段）

### 3.1 任务（任务DB）
- 触发：动词开头/明确行动表达
- 默认：`状态=收集`
- 推断：
- 含日期 → `状态=已排期` + `结束日期`（默认 09:00）
- 兼容：若仍存在旧选项名 `某一天`，视为与 `已排期` 等价
- 立即/尽快/今天完成 → `状态=下一个行动`
- 等…回复/外部依赖 → `状态=等候`
- 委托给X → `状态=委托`（标题括注）
- 取消/不做 → `状态=淘汰`
- 解析：`优先`(紧急/高/中/低)，`耗费精力`(极度/高/中/低)，`场景`(手机/电脑/家/网上购物)
- 自动关联优先级：项目 > 目标 > 领域
- 含 URL：同步创建资源并互相关联
- 子任务：识别清单/子步骤 → 建子任务并设置父/子关系

### 3.2 事件（事件DB）
- 触发：会议/约见/产检/DDL/里程碑/通话等 + 明确时间
- 必须：GMT+8；若有时间段要设置结束
- 默认：`日历=Personal`（可推断 Work）
- 自动关联：任务/项目；会议 URL → `会议链接`；@人名 → `相关人员`

### 3.3 资源（资源DB）
- 触发：URL/文件/收藏/收录/文章/视频/播客/课程/PDF/模板
- 默认：`状态=收集`，自动识别 `类别`（不确定可留空）
- AI 摘要：三段式（背景→要点→可行项）写入 `AI 摘要`，并给 3–5 条关键要点
- 自动关联：项目/目标/领域；命中知识维度 → 创建/补充 `主题`
- 若含行动要点：同步创建任务并互相关联

### 3.4 笔记（笔记DB）
- 触发：无 URL 的内部思考/会议纪要/研究记录/AI 生成内容
- 默认：笔记落到 **笔记DB**（不创建独立页面），`状态=收集`
- 自动关联：领域/项目/目标/任务/资源/主题

### 3.5 重点摘录 / 书籍（重点摘录DB / 书籍DB）
- 触发：摘录/金句/引用，或从资源/书籍抽取高亮
- 摘录：写 `AI 摘要`（语境），关联 `资源/书籍/主题`

## 4) 状态机（避免悬空）
- 任务DB：收集 → 已排期/下一个行动/等候/委托 → 已完成/淘汰
- 资源DB：收集 → 待审查（已摘要/打标签）→ 复习（设置下一次回顾）→ 存档
- 笔记DB：收集 → 草稿/永久 → 存档

                                                                  有了上面这些规则，就可以很容易地让 OpenClaw 帮你做下面这些事情：

                                                                  1. 任务与日程管理
                                                                    • 添加一个日程或任务
                                                                    • 列出未完成的任务
                                                                    • 推荐明天的安排
                                                                  2. 项目与领域追踪
                                                                    • 查看并列出你现有项目的完成情况
                                                                    • 查看各个项目所关联的任务
                                                                    • 查看你关心的各个领域最近的投入情况

                                                                  比如下面我先用它做一个简单的操作：把一个推特的链接丢给它并告诉它保存，然后它就能够按照我上面定的这些规则，把网页内容扒下来做个总结，并丢到资源 DB 里面打上对应的标签。

                                                                  它的灵活程度是非常高的，而且这些规则都是深度可定制的，可以根据你自己的习惯去给它做优化、做设计。

                                                                  # 3. 播客转阅读版本

                                                                  这个案例主要想讲的是，我是如何将一个复杂的工作流标准化为一个可复用的技能。

                                                                  我有听播客的习惯，但我总觉得听完之后，播客里的这些知识很难被再次回忆起来并加以利用。

                                                                  因为播客是音频形式，不能直接检索内容。如果你突然需要引用某一个播客里面的一段内容，你只能根据这个播客的名称找到对应的那一集，然后重听一遍，这样效率很低。

                                                                  于是我就有了把这种音频播客转换成文字阅读版本的诉求。虽然以后可能也不会再去看，但是万一需要用到的时候，我能找得到。

                                                                  于是我就把这个任务丢给了 OpenClaw。

                                                                  过程并不是一帆风顺，在转换的过程中遇到了很多问题：程序没响应、运行速度太慢、进度条不动、CPU 利用率不高等等。

                                                                  一开始使用 Whisper 原本的模型，可能是因为音频长度太长，直接卡死。它提议说使用 Faster Whisper 模型会快一点，但是转换一个 76 分钟的播客大概需要 70 多分钟，我觉得还是很慢。

                                                                  我问 Gemini，Gemini 建议使用 MLX Whisper，所以我又继续让它去做一个对比。

                                                                  最后评测结果如下：

                                                                  其实用到这里就已经很震撼了。这相当于是帮我去做了一系列的实验：实验环境是它自己去搭的，任务也是它自己去奔跑的。这些脏活累活它都义无反顾，吭哧吭哧直接帮你干完，把最终的结果给递上来，真的挺奇妙的。

                                                                  现在来进行最后一步了：将转写后的文字稿重写成阅读版本，清理掉多余的口头语和过长的篇幅，最终形成一个高度浓缩但又不失细节的文章。

                                                                  基于这个 MLX medium的结果按如下要求生成，我看一下，要注意可能逐字稿中的错误：

你将把一段播客重写成"阅读版本"，按内容主题分成若干小节；目标是让读者通过播客就能完整理解视频讲了什么，就好像是在读一篇 Blog 版的文章一样。
输出要求：
1. Metadata
- 标题
- 作者
- 网址
2. Overview
用一段话点明视频的核心论题与结论。
3. 按照主题来梳理
- 每个小节都需要根据视频中的内容详细展开，让我不需要再二次查看视频了解详情，每个小节不少于 500 字。
- 若出现方法/框架/流程，将其重写为条理清晰的步骤或段落。
- 若有关键数字、定义、原话，请如实保留核心词，并在括号内补充注释。
风格与限制：
- 永远不要高度浓缩！
- 不新增事实；若出现含混表述，请保持原意并注明不确定性。
- 专有名词保留原文，并在括号给出中文释义（若转录中出现或能直译）。
- 要求类的问题不用体现出来（例如 > 500 字）。
- 避免一个段落的内容过多，可以拆解成多个逻辑段落（使用 bullet points）。
- 内容要完整，如果由于输出限制提前结束要告知用户，允许用户输入“继续”来输出后续内容。

                                                                  很漂亮，就是我想要的，最后让它保存到 Notion。

                                                                  后面其实我又对这个流程进行了优化，找到了一个新的模型 SenseVoice，能够更高效地把语音转成文字。然后我再让它把这个流程提炼成一个可复用的 Skill，之后我就可以直接使用这个 Skill 去完成工作了。

                                                                  后面只需要把一个播客的链接直接丢给这个技能，它就能按你的这个流程把任务完成。

                                                                  # 4. 个人网站建设

                                                                  我一直都有维护着一个个人网站 https://timpcfan.site ，虽然基本上从不更新，也没有几篇文章，但我一直觉得个人网站是做技术的人的一张名片，所以得跟风搞一个。

                                                                  我的个人网站是一个静态网站，使用一个 GitHub 仓库来管理，在本地编辑 Markdown 文档，push 到 GitHub 仓库，触发 CI/CD 流水线，使用 VuePress 编译成网页，再自动发布到 Vercel 上面（参考的 LearnData 这个项目open in new window）。另外，我的域名使用 Cloudflare DNS 解析，图床采用 Cloudflare R2 对象存储。这一套都是免费的，除了域名，没有使用成本。

                                                                  这全套链路都有相应的开放 API 或 CLI 工具可以使用，对 Agent 很友好。于是就能实现让龙虾自动帮你发博客的效果：

                                                                  你可以简单一句话，它就这样水灵灵地、理所当然地把一个本来复杂的事情直接帮你完成。

                                                                  在我点开博客地址，看到派蒙写的最新文章时，那种感觉很奇妙。虽然背后的逻辑不复杂，但看到我这闲置了三年的个人网站上面，突然多了一篇文章，还不是我自己写的，挺震撼的。

                                                                  除了基本文章的发布，我还让它做了网站的运维。比如修复我这个网站的图床，让它把网站图床从原本的 BOS 上迁移到 Cloudflare R2 上。详见这篇文章吧：2026/03/19 - 把个人网站的对象存储从 BOS 迁到 R2open in new window

                                                                  # 6. 开源项目研究与快速部署

                                                                  现在 AI 时代，编程门槛不断降低，各种开源项目层出不穷。我们很难花时间去自己一个一个尝试，但是 AI 可以替我们做到这一点：

                                                                  1. 需求匹配与调研
                                                                    如果你有一个诉求，可以让它去搜索相关的开源仓库，并对比不同仓库的具体实现。

                                                                  2. 快速部署测试
                                                                    当你看到一些有意思的仓库时，可以直接让它部署在本地；或者像我一样，利用云服务器，甚至可以直接把开源项目部署到公网。

                                                                  3. 帮你做一些实验
                                                                    在本地对多个开源项目工具进行测试并打分，给出最好的那个。

                                                                  我经常会在公众号或其他地方刷到一些有意思的项目，但因为不确定它对我是否有价值，我就会给派蒙（小龙虾）派一个任务，让它帮我研究一下这个仓库。

                                                                  它可以帮你分析项目，或者基于你的需求点，看你是否需要关注这个项目。甚至你可以让它在本地帮你部署起来，方便你在本地试用。

                                                                  如果你有云服务器，你甚至可以远程让它在你的云服务器上进行部署，然后给你一个公网可访问的链接。
