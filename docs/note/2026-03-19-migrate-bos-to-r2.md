今天晚上，终于把个人网站里历史包袱最重的一块给搬掉了：**把原来挂在百度 BOS 上的静态资源，整体迁移到了 Cloudflare R2。**

这件事其实拖了挺久。网站这些年断断续续重建过很多次，图片、动图、压缩包、Anki 卡包之类的静态资源，也跟着平台一路漂流。最开始只是想先把站搭起来，资源放哪儿并没有那么讲究；时间一久，链接就慢慢沉淀成了一堆“能用，但不够安心”的历史遗产。

这次动手迁移，最直接的原因其实很朴素：**既然网站本体已经在持续维护，那资源层也该收拢到一个更统一、更可控的地方了。**

## 这次到底做了什么

这次迁移不是简单“传几张图”那么轻松，而是完整走了一遍资产核查流程：

1. 先进入旧的 BOS 对象存储目录，把历史资源逐页遍历出来；
2. 把对象一批一批下载到本地，确认实际文件都拿到了；
3. 扫描个人网站项目 `timpcfan.github.io`，把所有 `bcebos.com` 的资源链接全部抽出来；
4. 拿项目里引用到的对象名，和本地下载的文件逐个对账；
5. 确认引用资源都能在本地文件里找到之后，再统一上传到 R2；
6. 最后把项目里的旧 BOS 链接，全部替换成新的 R2 链接并重新发布。

真正麻烦的地方不是“上传”，而是**确认这批旧资源到底有没有漏、有没有重名、有没有历史残留**。这一步如果不做扎实，后面链接替换得再漂亮，线上也很容易冒出失效图片。

## 核查结果

最后核下来的结果还挺干净。

对于 `timpcfan.github.io` 这个项目：

- 一共扫描到 **836 处**旧对象存储链接引用；
- 去重后，对应 **188 个**实际对象；
- 这些对象在本地下载结果里都能找到对应文件；
- 上传到 R2 时，**188 个对象全部成功上传，没有失败项**；
- 项目里的旧链接也已经**全部替换完成**。

新的资源链接统一收口到了：

```text
https://img.timpcfan.site/imgs/<文件名>
```

也就是说，之后网站里的这批资源，不再依赖原来的 BOS 链接，而是统一走我自己的 R2 资源域名。

## 迁移过程中最有意思的一点

这次迁移里最容易让人误判的，不是资源本身丢了，而是**文件名和展示名并不总是完全一致**。

比如有些页面里写的是 `JPG`，但浏览器实际下载落盘的时候，扩展名会变成 `jpeg`；还有些对象在页面里看起来像没下到，最后一查本地，发现其实已经在 `Downloads` 里，只是名字被浏览器自动处理过了。要是不做最后一轮对账，很容易把“已经拿到的文件”误以为“还没迁完”。

所以到最后，真正重要的不是“页面上看起来像什么”，而是：

- 项目里引用的对象名是什么；
- 本地实际拿到的文件是什么；
- 新链接替换后，项目里还有没有旧域名残留。

把这三件事全核清楚，迁移才算真的完成。

## 结果

最终结果就是：

- 旧 BOS 资源已经迁到 R2；
- 网站源码里的旧链接已经全部替换；
- 变更已经提交并推送；
- GitHub Actions 构建与 Pages 部署也都顺利通过。

这类工作表面看起来不像“写一篇新文章”那样显眼，但其实特别像整理房间：平时不做，好像也能凑合；一旦收拾干净，整个系统都会轻松很多。

接下来如果还要继续折腾站点，我大概会优先沿着这个方向做下去：**让内容、资源、部署链路都尽量收口到自己可控的地方。**

毕竟，网站这种东西，真正舒服的状态不是“勉强能跑”，而是你知道它每一层都放在哪里、出了问题该去哪里修。

今晚这块，总算搬完了。
